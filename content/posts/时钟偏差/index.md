时间偏差常常成为域内渗透和横向移动的隐形障碍，尤其当利用 Keberos 票据、NTLM 身份验证和依赖时间戳的协议的时候，一旦渗透环境与自身主机或仿冒环境的时钟不同步，就会导致凭据验证失败或日志异常 Windows 默认对 Kerberos 请求有一个微小的时间偏差容忍范围，通常在五分钟左右，如果超过这个范围，域控制器会直接拒绝票据。

可以执行这样的命令：

```bash
sudo net time set -S 10.10.10.10
```

上面这个命令是 SMB 时间同步，一般走 TCP 445/139 端口，是 Windows 域常见的时间获取方式。

也可以使用 NTP 协议的方式进行时间同步，这是通过 UDP 123 端口完成的，如果是域控制器的话有极大的概率是开放的。

```bash
┌──(kali㉿kali)-[~/Work/BloodAD]
└─$ sudo ntpdate rebound.htb                                        
[sudo] password for kali: 
2026-08-05 09:37:58.566341 (-0400) +25174.985837 +/- 0.038636 rebound.htb 10.129.232.31 s1 no-leap
CLOCK: time stepped by 25174.985837
```

其中：
- 2026-08-05 09:37:58.566341 是当前本地时间和日期
- (-0400) 是本地时区偏移，表示与 UTC 时间相差 -4 个小时
- +25174.985837 表示本地时间与目标时间的差值，单位为秒。本地实际比目标时间慢了约 25174.99 秒
- +/- 0.038636  表示同步范围误差
- s1 表示 NTP 服务器的第一层
- no-leap 表示当前没有闰秒调整
- CLOCK: time stepped by 25174.985837 表示本地时钟被大幅调整了 25174.985837 秒
