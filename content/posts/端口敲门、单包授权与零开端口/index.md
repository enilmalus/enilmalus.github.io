## 端口敲门

端口敲门（port knocking）技术是一种基于隐蔽认证的安全机制，允许在默认关闭所有入站端口的情况下，仅通过特定顺序的端口访问来动态开放特定服务。其核心思想是服务器在初始状态下屏蔽所有连接，只有当客户端按预设顺序向多个端口发送数据包时，服务器才能识别合法模式并临时修改防火墙规则，允许特定 IP 访问受保护的端口，比如 SSH、RDP、Web 服务等。这种方式可以隐藏关键端口，防止端口扫描工具探测到开放的服务，从而降低被攻击的风险。

实现端口敲门通常依赖 knockd 这类监听工具，它监测入站数据包，识别预定义的敲门序列，并在匹配成功后执行相应的防火墙命令。例如，可以配置规则服务器在接收到 `7000->8000->9000` 端口顺序连接后，动态放行 SSH 端口，同时可以设定 `9000->8000->7000` 作为关闭 SSH 端口的敲门序列。客户端只需要发送正确的敲门请求，就能临时开启远程管理端口，使用 SSH 连接服务器，操作完成后再敲门恢复防火墙规则，确保端口重新关闭。

这种方式的优点在于可以有效减少攻击面，避免端口扫描暴露服务，适合用于保护 SSH 等关键管理端口，同时不需要额外的 VPN 或复杂的加密认证方案，资源占用极低。然而，端口敲门也有明显的局限性，比如攻击者能监听流量，就可能获取端口序列并复现攻击。此外，每次访问都需要先发送敲门序列，增加运维成本。为了解决这个问题，可以使用更安全的 `单包授权（SPA）` 机制，例如 fwknop 这类工具，它通过 GnuPG 加密的单一 UDP 数据包进行认证，避免传统敲门方式可能被监听和重放的风险。

在实际应用中，端口敲门适用于 SSH 服务器的控制访问、隐藏数据库和管理面板等关键服务、以及提供短期远程管理权限，特别是在企业安全策略中，可作为 `零开端口（Zero Open Port）` 方案的一部分，有效减少暴露面，提高服务器安全性。

下面是端口敲门的命令演示：

knock 敲门演示：

```bash
┌──(kali㉿kali)-[~/Work/Kali]
└─$ knock -v 10.10.10.45 197 719 801 983
hitting tcp 10.10.10.45:197
hitting tcp 10.10.10.45:719
hitting tcp 10.10.10.45:801
hitting tcp 10.10.10.45:983
```

nc 敲门演示：

```bash
┌──(kali㉿kali)-[~/Work/Kali]
└─$ for port in 197 719 801 983 ; do nc -zv 10.10.10.45 $port;sleep 1; done
```

解释一下这个 nc 命令，先循环这四个端口，依次赋值给 $port ，接着 nc 使用 -z 零模式，只尝试连接，不发送任何数据，连接成功说明端口开放，-v 详细输出，显示连接结果，暂停 1 秒接着执行。

## 单包授权（SPA）

单包授权（SPA，Single Packet Authorization）是一种通过单个网络数据包完成身份验证，从而零食开放访问权限的安全技术。未通过认证前服务对外不开放，只有合法客户端发出一个携带认证信息的单包（可以是 UDP/TCP/ICMP，内涵加密后的身份信息、令牌等），通过认证后才会临时开放服务。

传统 TCP/IP 的原则为 先连后验，端口必须对外开放，连接建立后才做认证。

## 零开端口（Zero Open Port）

零开端口（Zero Open Port）就是对外关闭所有端口，无任何服务监听。
