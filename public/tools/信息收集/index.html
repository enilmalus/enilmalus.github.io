信息收集的本质是扩大攻击面，从已知的点尽可能扩展出更多的资产和入口。

被动收集是不直接接触目标，靠第三方数据（证书透明度、网络空间测绘、搜索引擎、Github 泄露），优点是隐蔽、不触发告警。

主动收集是直接探测（端口扫描、目录爆破）。

实战里先被动后主动，先把不碰目标能拿到的信息收集全了，再主动探测。

维度上分为：域名层（子域名枚举、证书透明度找隐藏资产）、资产层（旁站、C 段、测绘引擎扩资产）、服务层（端口/指纹识别）、内容层（目录爆破、备份文件、敏感信息）、组织层（人员信息用于后续钓鱼）。

旁站

旁站等同于同一台服务器（同一个 IP）上的其他网站。

原理是虚拟主机：一台服务器靠不同域名（Host 头）区分，可以托管几十上百个站点，这些站点公用同一个 IP、同一套底层环境。所以如果目标站放的很死可以寻找一个相对弱的站拿到服务器权限。

拿到目标 IP 后做 IP 反茶域名（在线工具或测绘引擎），列出同 IP 的所有域名。

C 段

C 段等同于和目标 IP 处再同一个 /24 子网（前三段相同的那 256 个地址）。

比如目标是 1.2.3.45，那么 1.2.3.1 到 1.2.3.254 就是它的 C 段。企业往往会买一整段连续 IP，所以这个段里很可能有同一家单位的其他资产（OA、测试机、监控、打印机 等）。C 段扫描就是把整段扫一遍，找同属目标更脆弱的主机，打下来再横向移动到真是目标。

FOFA

FOFA 是国内的网络空间测绘搜索引擎，可以持续扫描全网并把所有联网资产的指纹（IP、端口、协议、网站标题、组件版本、证书 等）建成检索，可以使用查询语法去检索。

基础语法：

  • domain=“example.com” —- 按主域名找该单位所有相关资产。
  • ip=“1.2.3.45” 或 ip=“1.2.3.0/24” —- 按 IP 或整个 C 段查
  • port=“3389” —- 找开放
  • title=“后台管理” —- 按网页标题找
  • app=“Apache” —- 找特定中间件
  • body=“关键词” —- 寻找正文某字符串
  • icon_hash="" —- 按网站图标的 hash 找

Shodan

Shodan 是更老牌、偏全球和设备/物联网方向的测绘引擎，国外资产、ICS、摄像头、数据库这类暴露面比 FOFA 更全。思路和 FOFA 一样。

  • port:22
  • net:1.2.3.0/24 —- C 段
  • hostname:example.com
  • org:“公司名”
  • country:US
  • product:nginx
  • ssl:“example·”

信息收集步骤

一般遵循 资产发现 -> 服务识别 -> Web 枚举 -> 敏感信息挖掘 -> 攻击面分析 流程。

首先通过 FOFA 等方式收集主域名、子域名和公网资产，尽可能扩大攻击面。如何使用 nmap 发现开放的端口，然后进一步识别服务、版本和操作系统的信息。

针对 Web 服务，使用 WahtWeb 等工具识别中间件和开发框架，然后再利用 ffuf、dirsearch、gobuster 进行目录和接口枚举，重点关注后台管理页面、备份文件、上传接口等敏感路径。

最后再根据具体情况进行 Google Hacking、Github 搜索 等方式挖掘敏感信息，例如接口地址、API key、数据库配置、历史备份。

如果发现一个 API key、接口地址怎么办

如果在信息收集阶段发现了一个 API key 和接口地址，先确认 Key 的类型以及是否有效，随后分析接口的认证方式、请求参数和返回数据，了解它对应的业务功能。接着，围绕接口进行 API 枚举，寻找同类接口和隐藏接口，并重点验证是否存在未授权访问、水平或垂直越权、敏感信息泄露、上传漏洞以及业务逻辑漏洞等问题。

如果 API key 属于第三方云服务，先识别其类型，并在授权测试范围内验证其权限边界，判断是否存在配置过大的风险。整个过程的核心目标不是单独利用一个 Key，而是把它作为攻击面的一个切口，结合接口、身份认证和业务逻辑分析，评估其是否能形成完整的攻击路径。

Google Hacking 如何发现敏感文件、备份文件和后台入口

先用 site: 限定目标域名，再结合 filetype:、intitle:、inurl: 等语法查找敏感资源。例如使用 site:example.com filetype:zip 或者 filetype:sql 寻找可能误公开的备份文件和数据库导出；使用 intitle:login、inurl:admin 搜索后台登录入口；使用 swagger、api 等关键词定位 API 文档或测试接口；还会搜索 pdf、xlsx、docx 等文件类型，查找公开的运维文档、通讯录或者配置说明。
