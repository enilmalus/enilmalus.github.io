原理

XSS 是用户输入混进了 HTML 页面，被浏览器当作 JavaScript/HTML 代码执行。

具体来说就是网站把用户输入（评论、昵称、搜索词等）未经处理就拼进了返回给浏览器的页面里。如果输入的是 <script>alert(1)</script>，浏览器分不清这是该显示的文本还是该执行的脚本，就把它当脚本跑了。于是攻击者的 JS 就在受害者的浏览器、目标网站的上下文里执行了。脚本一旦在目标站的上下文运行就能读到该站的 Cookie，发送站请求、该页面，权限等同与受害人。

XSS 的三种类型

反射型

输入从请求里来，立刻被反射回当前响应的页面，不存数据库。典型的是搜索框、报错回显，payload 藏在 URL 参数里。利用方式是构造一个带恶意参数的链接诱导受害人点击，需要社工投递、一次性、只影响点链接的人。

存储型

payload 被存进了数据库（评论、留言、个人资料），之后浏览该内容的用户都会中招，危害最大。

DOM 型

漏洞完全发生在前端，服务器返回的页面本身没有问题，是页面里的 JS 把用户可控数据直接写进了危险的 DOM 操作（innerHTML、document.write、eval）。payload 甚至可能不发到服务器，所以服务端的 WAF 和过滤完全可能看不到它。

防御

重点在输出而非输入，同一份数据输出到不同位置（HTML 标签内、属性里、JS 里、URL 里）需要的编码方式不同，所以该在输出到页面的那一刻按上下文做对应编码。
